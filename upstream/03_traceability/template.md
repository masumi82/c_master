## 3. 逆引き（設計項目から要件へ）
基本設計にあるが、どの要件にもつながらない項目を探す。見つかったら、要件に追加するか設計から削る。

| 基本設計の章・項目 | 対応する要件 ID | 判断 |
|---|---|---|
| | （なし） | 要件に追加 / 削る |

## 4. 確認の仕方
- 1章と2章の「基本設計の章・項目」列に空欄がないか。空欄は設計漏れ
- 1章の「受入テストの観点」が、顧客の言葉で書かれているか。「レジスタの値が〜」は受入テストではない
- 3章に行があるか。行がないなら、逆引きをしていない可能性が高い（設計には要件にない判断がふつう混ざる）

## 受入テストと結合テストの違い
- 受入テストは顧客が確認する。装置を使って業務ができるか。「ランプが光ったらボタンで消せる」
- 結合テストは開発側が確認する。モジュール同士がつながるか。「UART から `set hi 35` を受けると、設定モジュールの上限が 35 になり、`OK` を返す」
- 単体テストは今回の範囲外。C の演習で Unity で実行したものがそれにあたる
