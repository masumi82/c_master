# 要件定義書のレビュー観点

レビューする人（Claude を含む）はこの一覧を基準に見る。各項目には雛形の章番号を付けてある。

## 目的・スコープ（1〜2章）
- [ ] 目的が顧客の業務の言葉で書かれているか。「温度監視システムを構築する」は目的ではなく手段
- [ ] 対象外の節に、顧客が口にした要望のうち今回やらないものが理由付きで書かれているか（依頼メモには少なくとも2つある）
- [ ] 前提と制約に、予算・納期・設置環境・既存設備が書かれているか

## 利用者（3章）
- [ ] 利用者ごとに「何を操作するか」と「技術的な知識」があるか。現場の人と事務所の人は分けられているか
- [ ] 通信経路の距離が書かれているか（これが決まらないと 7章の物理層が決まらない）

## 機能要件（5章）
- [ ] すべての要件に ID があり、1行1要件か。「AしてBする」は2つに分ける
- [ ] 「すぐに」「たまに」「簡単に」「適切に」「必要に応じて」が残っていないか。残っているなら 8章で定義されているか
- [ ] 各要件に根拠（依頼メモか議事録のどこか）があるか。根拠がない要件は、書き手の思い込みか、隠れた前提
- [ ] 依頼メモの要望がすべて、要件か対象外のどちらかに現れているか。抜けを探す
- [ ] 異常系が書かれているか。センサが壊れたら、ケーブルが抜けたら、停電から復帰したら
- [ ] 両立しない要望について、どう決めたかが要件として書かれているか（依頼メモに少なくとも1組ある）

## 非機能要件（6章）
- [ ] 数値があるか。「10分以内に検知」「10分間隔で記録」「7日分保持」のように
- [ ] 数値の根拠が議事録にあるか。書き手が勝手に決めた数値は 9章の未決事項に「顧客確認」として載っているか
- [ ] 停電時と復帰時の振る舞いが、装置が持つ状態のそれぞれについて書かれているか（何を持つかは 6章と 7章から拾う）

## 外部インターフェース（7章）
- [ ] PC との接続について、物理（ケーブル種別、距離）と論理（方式）が分かれて書かれているか
- [ ] センサとの接続について、設置場所と装置本体の距離が要件に反映されているか

## 用語・未決事項（8〜9章）
- [ ] 顧客の言葉（ランプ、おかしい、ボタン）が用語で定義されているか
- [ ] 未決事項が空でないか。空なら、決めたつもりになっていることを疑う
- [ ] 未決事項に担当と期限があるか

## 文書全体
- [ ] 顧客が読んで理解できる言葉か。型番や略語が説明なしに出ていないか
- [ ] 基本設計の内容（部品の選定、内部構成、コマンドの文字列）が混ざっていないか。混ざっていたら 2日目に送る
